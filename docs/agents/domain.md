# Domain docs

This is a single-context repo. Before exploring or changing domain behavior, read `CONTEXT.md` at the repo root and any relevant ADRs in `docs/adr/`.

If an ADR directory or a domain document does not exist, proceed silently. The domain-modeling skill creates them when a term or decision needs recording.

Use the terms defined in `CONTEXT.md` in issues, specs, proposals, and tests. Avoid the synonyms it rejects. If a concept is missing, check whether it needs a new domain term before naming it in a spec.

If a proposal conflicts with an ADR, name the conflict and explain why revisiting the decision is warranted.
